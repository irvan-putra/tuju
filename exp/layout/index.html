tuju layout experiments

Can automatic tools place the tuju route map better than hand placement? Ran 23 Nov 2026 against the 0.2.14 map geometry. Short answer: not yet. Neither candidate was adopted; the hand-placed layout stays.

What was tried

Three small dependency-free tools, documented in tools/LAYOUT_PROPOSALS.md. They measure and search; they never change the map on their own.

  • tools/score_route_map.py scores a built map: line crossings, bends, closest approach of different lines, and text boxes a line touches. Every build prints the score, so any layout change has a number to beat.
  • tools/route_walk_links.py routes one walking link by A* search on a grid: label boxes are blocked, crossings and turns cost.
  • tools/pack_columns.py packs the map's movable blocks by simulated annealing, minimising link length and bends.

All score numbers are estimates (estimated label widths, discretized curves). They compare variants; they are not verified layout quality.

Experiment 2: pack the corridor blocks

With the main network pinned and blocks allowed to slide, the packer lowers its proxy link cost from 5155 to 4587 (−11%, stable across seeds): move the S61 block about 320 units right; S11 is already optimally placed. But the gain does not survive the real geometry:

  • A naive translation of the S61 block sends a connector through the Grand Indonesia note: estimated text overlaps 20 → 29.
  • Redrawing the links as straight drops collides with the moved block's own header labels: 20 → 24, crossings unchanged.

A smaller shift with re-anchored labels is untested. Not adopted. Full packed variant: variant-packed.svg. Raw numbers: pack-trial.json.

Conclusion

Neither candidate beat the hand-placed layout once text clearance was checked, so nothing was adopted from these trials. The tools stay in the repo (tools/ and experiments/) and the build keeps printing the score, so future layout ideas get measured the same way. Layout improvements since have been placed by hand and checked with the same scorer.
